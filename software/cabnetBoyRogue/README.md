# cabnetBoy Rogue — CH32V003 턴제 로그라이크: 설계 & 구현 가이드

CH32V003A4M6 (16 KB Flash / 2 KB SRAM) 에서 도는 **턴제 그리드 로그라이크**를
`software/cabnetBoyRogue/` 에 스캐폴딩했습니다. **실제로 빌드되며 크기를 실측**했습니다.

```
RAM:   524 / 2048 bytes  (25.6%)
Flash: 6288 / 16384 bytes (38.4%)      ← 기존 Arkanoid 펌웨어는 13588 (82.9%)
```

---

## 1. 먼저: 기존 `software/cabnetBoy` 코드 리뷰

### 1-1. 정체
지금 있는 `src/main.c` 는 **로그라이크가 아니라 벽돌깨기(Arkanoid)** 입니다.
wagiminator의 `CH32V003-GameConsole` / `Tiny Arkanoid` 포팅에 DaftWork가 가변저항
입력 2개를 덧붙인 상태입니다 (`Ballxpos`, `TrackBar`, `BlocsGrid[6][5]`, `LEVEL[]`).

### 1-2. 실측 사용량 (toolchain으로 직접 확인)
| | Flash | RAM |
|---|---|---|
| `software/cabnetBoy` (Arkanoid) | 13,588 / 16,384 (**82.9%**) | 4 / 2,048 |
| `software/cabnetBoyRogue` (신규) | 6,288 / 16,384 (38.4%) | 524 / 2,048 |

남은 Flash가 **2.8 KB뿐**이라 로그라이크를 기존 프로젝트에 얹는 건 사실상 불가능합니다.
→ **새 프로젝트로 분리**(한 것)하고 Arkanoid는 참고용으로 남겨두는 게 맞습니다.

### 1-3. 버그 / 문제점

**(1) ADC 채널 복원 누락 — 잠복 폭탄** `src/driver.h:83-101`
```c
static inline uint8_t Get_PIN_R_SLIDER(){ ADC_input(PIN_R_SLIDER); ... ADC_read(); }
static inline uint8_t JOY_up_pressed(void){ uint16_t val = ADC_read();  // 채널 재선택 없음!
```
`ADC_input()` 은 ADC 먹스를 바꾸는 전역 상태입니다. `Get_PIN_R_SLIDER()` /
`Get_PIN_R_ROTATE()` 를 한 번이라도 호출하면 **그 뒤 모든 방향키 읽기가 슬라이더
채널을 읽습니다.** 지금은 `main.c` 가 이 함수를 호출하지 않아 잠복 상태지만,
슬라이더를 쓰는 순간 방향 입력이 통째로 깨집니다.
→ 항상 `ADC_input(PIN_PAD)` 를 먼저 호출 (새 `retro_pad()` 는 그렇게 되어 있음).

**(2) DOWN 버튼이 인식되지 않음** `src/driver.h:33`
래더 저항으로 계산한 실제 값 (VDD 무관, 래칭비):
```
UP   = 2k/(2k+8k2)  = 0.196*VDD → ADC 201
DOWN = 2k/(2k+3k9)  = 0.339*VDD → ADC 347
LEFT = 2k/(2k+2k)   = 0.500*VDD → ADC 511
```
그런데 `JOY_S = 300`, `JOY_DEV = 20` → 280~320 만 DOWN으로 인정 → **347은 탈락**.
즉 지금 펌웨어에서 **패들을 아래로 내릴 수 없습니다.**
→ `JOY_S` 를 347로, `JOY_DEV` 는 25~30 권장. `software/calibrator` 로 실측 확인 가능.

**(3) RIGHT 는 이 하드웨어에 없음** `src/driver.h:31,34,36`
`JOY_E=90 / JOY_NE=259 / JOY_SE=388` 은 원래 **8방향 조이스틱** 래더 값입니다.
cabnetBoy PCB에는 택트 스위치가 UP/DOWN/LEFT/ACT **4개뿐**입니다 (R7/R8/R10 + ACT).
→ `JOY_right_pressed()` 는 절대 참이 되지 않습니다.

**(4) float 사용** `src/main.c:252`, `src/spritebank.h:35-42`
```c
float CORECTIONY = (VAR->SIMBallSpeedy) + (VAR->TrackAngleOut/100.00);
```
CH32V003은 **RV32EC — 곱셈/나눗셈 명령도, FPU도 없습니다.** float 한 줄이
`__mulsf3/__divsf3` 소프트플로트를 끌어오고, `GROUPE` 구조체만 48바이트입니다.
로그라이크는 **정수만** 쓰세요 (새 코드에는 float이 한 개도 없습니다).

**(5) 초기화 안 된 변수 사용** `src/main.c:50, 394`
`GROUPE VARIABLE;` 이 초기화 없이 선언되고, 첫 `ResetBall()` 이 `VAR->Frame` 을
읽습니다 → **첫 판 볼 속도가 미정** (스택 쓰레기값에 따라 달라짐).

**(6) 렌더 함수가 전역 상태에 의존** `src/main.c:347-369`
`background()` 가 `static uint8_t SWIFT_TEXTURE` 를 호출마다 갱신합니다.
`Tiny_Flip()` 이 픽셀을 어떤 순서/범위로 훑느냐에 따라 결과가 달라집니다(재진입 불가).

**(7) unsigned 비교로 죽은 코드** `src/main.c:313`
```c
if ((X-(uint8_t)(BALLXPOS))<0) return 0x00;   // uint8_t - 항상 거짓
```

**(8) 헤더에 비-static 정의** `src/driver.h:138,152,165`
`JOY_sound()`, `rnval`, `map()` 이 헤더에 그냥 정의되어 있어 `.c` 파일이 2개만
되어도 **중복 심볼 링크 에러**가 납니다.

**(9) `abs()` 매크로** `src/driver.h:163` — 인자 2회 평가, unsigned에서 항상 참.

**(10) I2C 무한 대기 / 워치독 없음** `src/i2c_tx.c:59-64`
OLED가 응답하지 않으면 부팅이 그대로 멈춥니다. `IWDG` 도 없음.

> **결론**: 기존 `cabnetBoy` 는 손대지 말고(Arkanoid로 보존) 새 프로젝트에서
> 처음부터 쓰는 것을 권합니다. 새 코드는 위 10개를 모두 피해서 작성했습니다.

## 2. 하드웨어 제약 (설계의 출발점)

| 항목 | 값 | 게임 설계에 미치는 영향 |
|---|---|---|
| Flash | 16 KB | 폰트/타일/맵 데이터를 아껴야 함 |
| SRAM | 2 KB | **1 KB 프레임버퍼를 쓰면 안 됨** |
| 코어 | RV32EC, 48 MHz(현재 12 MHz) | 곱셈/나눗셈/float 전부 소프트웨어 |
| 디스플레이 | SSD1306 128x64, I2C 400 kHz | 전화면 전송 ≈ **24 ms** (8페이지 × 128B) |
| 입력 | UP/DOWN/LEFT 래더 + ACT | **4방향 직접 입력 불가** (§3) |
| 부저 | PA2 (PNP, LOW=소리) | 턴 기반이라 블로킹 재생으로 충분 |
| EEPROM | HT24LC64 8 KB (I2C 0x50) | 세이브/하이스코어용 — 단 **WP 핀 플로팅 수정 필요** |

**핵심 통찰**: "24 ms에 전화면을 다시 그릴 수 있다" + "턴제라 초당 수십 프레임이
필요 없다" → **프레임버퍼도, 더블버퍼도, 부분 갱신도 필요 없다.** 매 턴 전화면
재생성이 가장 단순하고 가장 안전한 선택입니다. (그래서 RAM이 524 B로 끝납니다.)

## 3. 컨트롤 설계 — 이 프로젝트에서 가장 중요한 결정

### 3-1. 왜 4방향을 버튼으로 못 만드는가
래더에 스위치 3개(8k2 / 3k9 / 2k) + 풀다운 2k 이므로 조합값은:

| 누른 버튼 | 저항 | ADC(10bit) |
|---|---|---|
| 없음 | ∞ | 0 |
| UP | 8k2 | 201 |
| DOWN | 3k9 | 347 |
| LEFT | 2k | 511 |
| UP+DOWN | 2.63k | 442 |
| UP+LEFT | 1.61k | 567 |
| DOWN+LEFT | 1.32k | 616 |
| 전부 | 1.03k | 675 |

저항 5% 공차까지 넣으면 UP+DOWN(417~468) vs LEFT(486~537) 간격이 **18 카운트**까지
좁아집니다 → 두 버튼 동시 누르기를 4번째 방향으로 쓰는 건 **불안정**. 쓰지 마세요.

### 3-2. 채택한 방식: 회전 + 전진 (rotate & step)
버튼 3개로 4방향을 모두 얻는 검증된 방법입니다.

| 입력 | 동작 |
|---|---|
| **UP** | 바라보는 방향으로 한 칸 전진 (몬스터가 있으면 공격) |
| **LEFT** | 반시계 회전 (턴 소비) |
| **DOWN** | 시계 회전 (턴 소비) |
| **ACT** | 줍기 / 계단 내려가기 / 대기 |
| *(보너스)* **RV09 노브** | 돌리면 회전 (PD4, 배선 정상) |

화면의 `@` 는 항상 "바라보는 방향으로 걷는" 캐릭터라 조작이 금방 익숙해집니다.

### 3-3. 대안 (원하면 바꿀 수 있음)
- **노브로 방향 선택**: 노브를 4섹터로 나눠 방향 지시계로 쓰고 ACT로 이동.
- **U5 슬라이더 사용**: 지금은 하드웨어 배선 오류로 항상 VCC를 읽습니다
  (PCB 리뷰 2-1). **U5.1=VCC, U5.3=GND, U5.2(와이퍼)=R_Slider** 로 고친 뒤에만 사용 가능.
- **사이드뷰 턴제 로그라이크**: LEFT/RIGHT/UP + ACT 조합이 더 자연스러움.

    ├── gfx.h   / gfx.c       ★렌더러: 8x8 셀 → SSD1306 페이지 스트리밍

### 5-1. 렌더러 원리 (`gfx.c`)
SSD1306은 **8픽셀 높이의 페이지 8장** 구조입니다. 8x8 타일 하나는 정확히
"페이지 1장 안의 가로 8픽셀" 이므로, 타일 1개 = 페이지당 **1바이트 × 8열**입니다.

```c
gfx_begin(page);            // 128 B 버퍼 클리어
  gfx_cell(col, value);     // value<32 → 지형 타일, 32~95 → 폰트 글리프
gfx_send();                 // I2C로 128 B 전송 (≈3 ms)
```
타일 데이터는 사람이 읽기 쉬운 **행 단위(row-major)** 로 저장하고, 그릴 때
8x8 비트 전치(transpose)만 수행합니다. 조회 테이블 없이 64회 비트 연산이라
페이지당 수백 사이클 — **1 KB 프레임버퍼를 SRAM에 두는 것보다 훨씬 이득**입니다.

### 5-2. 폰트 (`font8.h`)
윈도우에 있는 **DejaVu Sans Mono**(Bitstream Vera/DejaVu 라이선스, 자유 사용)를
11px로 래스터라이즈 → 8x8 셀에 맞춰 임계값 처리해 자동 생성했습니다.
Lucida Console 같은 시스템 폰트를 ROM에 굽는 라이선스 문제를 피했습니다.
ASCII 32~95만 저장(512 B)하고 소문자는 렌더 시 대문자로 접습니다 — 고전 로그라이크 룩.

### 5-3. 보드 계층 (`retro.c`) — 기존 코드의 버그를 피한 부분
```c
uint16_t retro_pad(void){ ADC_input(PIN_PAD); return ADC_read(); }  // 채널 항상 재선택
```
부저, RNG(xorshift16), 슬라이더/노브 읽기까지 이 파일 하나에 격리했습니다.

## 6. 게임 규칙 (마일스톤 1 — 지금 동작하는 것)

- **던전**: 32×16 타일, 방 4개(중복 배치 거부 샘플링) + L자 복도로 연결, 2비트/타일
- **시야**: 반경 7, Bresenham 라인으로 벽 차단 판정(섀도캐스팅보다 가볍고 충분)
- **기억**: 지나간 곳은 `seen` 에 남아 지형만 흐리게 유지, 몬스터/아이템은 안 보임
- **몬스터 4종**: R(쥐) / G(고블린) / S(뱀) / O(오크) — 보이는 동안만 플레이어 쪽으로 접근, 인접 시 공격
- **아이템**: `!` 포션(HP+6), `$` 골드
- **계단** `>` 에서 ACT → 다음 층(깊이+1, HP+3, 몬스터 수/강도 증가)
- **전투**: 플레이어 데미지 = 1 + rand(2) + depth/3, 몬스터는 종류별 고정
- **상태줄**: `HP09/12 L03 G007` / **메시지줄**: `IT HITS YOU`

### 턴 루프
```c
for(;;){
  render();                    // 전화면 재생성 ≈ 24 ms (턴제라 문제 없음)
  key = wait_key();            // 디바운스 + 떼기 대기 (+ 노브 회전)
  switch(key){ UP:전진, LEFT/DOWN:회전, ACT:행동 }
  monsters_turn();             // 몬스터가 한 턴씩
  fov_update();                // 시야 재계산
  if(!hp){ game_over(); new_game(); }
}
```

| M | 내용 | 힌트 |
|---|---|---|

| M5 | 상점, 보스, 시야 제한(횃불 연료), 시드 공유 | 시드 RNG를 EEPROM에 저장 |
